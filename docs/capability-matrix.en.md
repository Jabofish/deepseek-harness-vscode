# Capability matrix

[English](capability-matrix.en.md) | [简体中文](capability-matrix.md)

This matrix records each capability's current scope, limits and status. Advanced operations depend on the connected DSH capability declarations.

## How to use this matrix

Use the stable capability ID in issues, PRs and agent tasks. Update the relevant scope description when behaviour changes. Complete the required native DSH, VS Code and manual validation before raising a status; leave it `PARTIAL` when evidence is missing. Record the connected Host/profile and actual results using the [testing guide](quality.md#report-test-results). Installation, interaction and privacy instructions are in the [user guide](../README.md); version-specific contracts are in the [upstream contract](dsh-contract.en.md).

| Status    | Meaning                                                                           |
| --------- | --------------------------------------------------------------------------------- |
| `DONE`    | The capability is usable across its required scenarios, with acceptance complete. |
| `PARTIAL` | Usable behaviour exists, with scope limits or scenarios still to verify.          |
| `TODO`    | No usable implementation is available.                                            |

## Product boundaries

- File editing, Explorer, terminal and splits use VS Code's native facilities. The extension does not recreate DSH Web's Dock, file tree, PTY terminal, browser or Office preview.
- Remote workspaces use workspace-side DSH and filesystems. Connecting an external DSH does not map its filesystem automatically.
- Models, providers, presets, commands, tools, Skills, plugins and optional services come from upstream structured catalogues. Catalogue search requires an upstream interface.
- Approvals, questions, Goals, background tasks, Workflows and tool states come from structured interfaces/events.

See the [upstream contract](dsh-contract.en.md) for version/interface differences, [architecture](architecture.en.md) for layers/security, and [testing guide](quality.md) for validation and release requirements.
