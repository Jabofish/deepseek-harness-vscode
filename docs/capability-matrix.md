# 能力矩阵

本表只陈述**当前功能边界、验收缺口和证据等级**。它不是实施日志。DSH 精确版本及可用 wire 以 [上游契约](dsh-contract.md) 为准；通用跨层和安全规则见 [架构](architecture.md)。每次能力变化只修改对应 ID 的一行，并在 PR/测试记录保存具体运行结果。

- `DONE`：代码、适用的自动测试及该能力要求的真实 DSH/VS Code 验证均已完成。
- `PARTIAL`：已有实现或自动证据，但仍缺列出的负面、现场、跨平台或可访问性证据。
- `TODO`：尚无可验收实现。`PARTIAL` 不因构建通过自动升级为 `DONE`。

目前下列项目均为 `PARTIAL`；“已有自动覆盖”只说明测试层，不代表真实运行。稳定证据入口是 `packages/*/test/`、`apps/*/src/**/*.spec.ts*`、`tests/live-dsh/`、`tests/vscode-e2e/` 和对应 PR；没有记录明确版本与结果的运行不能用于提升状态。

## 产品边界

本扩展使用 VS Code 原生编辑器、资源管理器、终端和分栏，不复制 DSH Web 的 Dock、独立文件树、PTY Terminal、Browser、Office 预览或桌面端专属窗口；已有 Host 打开入口不等于实现 DSH Terminal Controller 或 `workspaceFiles` API。插件 inventory 与完整 Plugin Manager 是不同能力；上游没有通用 registry 搜索 Remote 时不伪造搜索。可选 MCP、LSP、Schedule、Plugin、Workflow、Ralph 与第三方工具必须从结构化目录或能力声明发现，不硬编码清单、不把模型文本当状态。

补充验收时只更新对应行的**当前**事实与缺口；产品变化写 [更新日志](../apps/extension/CHANGELOG.md)，协议规则写 [上游契约](dsh-contract.md)或[架构](architecture.md)。不新增日期审计、缺陷流水、运行号和原始终端输出。
