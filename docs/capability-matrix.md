# 能力矩阵

这是功能范围的唯一清单。文档只描述当前能力、完成条件和状态，不承载审计日记、缺陷流水、原始终端输出或逐次变更记录。用户可见的版本变化只记录在 [版本更新日志](../apps/extension/CHANGELOG.md) 中。

## 状态规则

- `DONE`：代码、自动测试和所需的真实 DSH / VS Code 运行验证全部完成。
- `PARTIAL`：已有部分实现或自动测试，但仍缺真实运行、负面路径、跨平台、可访问性或发布证据。
- `TODO`：尚未形成可验收实现。

没有真实运行证据的能力不得因为构建成功而标为 `DONE`。未知 DSH 版本只允许使用已经核对过的 wire 做只读兼容探测；版本专属字段、事件和 Session wire 必须精确匹配，无法支持时返回 `CAPABILITY_UNAVAILABLE`。

## 当前基线

- 扩展发布目标为 `0.2.3`，本批内容见 [版本更新日志](../apps/extension/CHANGELOG.md)。
- 已知 DSH 版本按真实协议边界使用独立 Adapter：legacy Host、alpha family v0、Session v2、Session v3 和 Session V4 不跨 wire family 猜测。新增 `0.1.5-rc.3`、`0.1.7-alpha.2`、`0.1.7-rc.1`、`0.1.7-rc.2` 均有独立精确入口；rc.2 代码和契约测试已覆盖，真实 DSH 运行未验证；安装器默认仍使用 npm `latest` 的精确版本 `0.1.5-rc.3`。
- DSH `0.1.6-alpha.1` 有精确 `alpha161` Adapter：managed `--no-open` 启动、`mode=exact` 探测、只读 surface 与 transcript 归约已在 npm alpha 通道的真实运行时上通过 smoke，Connection/Gateway 与 Session v3 基础 wire 复用已核对的 `rc152` 边界，`image/offload` 仅按脱敏 opaque 保留；精确识别不代表消息投影 UI、终端、权限预设、归档恢复等新增 surface 已实现，具体范围见下表。
- DSH `0.1.6-alpha.2` 有精确 `alpha162` Adapter：`session/control` 按 `jobs`/`projections.inbox` 归约队列与 Steer，`session/writer-held` 归一化为可重试的忙碌错误，契约 fixture 覆盖基线/增量、畸形拒绝、mux 取消与释放，managed 真实运行时的 `tests/live-dsh` smoke 已通过；VS Code/Webview 现场回放和跨平台发布矩阵未完成，故适配证据保持 `PARTIAL`。
- DSH `0.1.7-alpha.1` 有精确 `alpha171` Adapter：Session V4、projection-only `session/control`、Workspace pinned baseline、独立 Job Controller 的 list/follow/kill、registry-only preset roster 和 plugin inventory 均由隔离版本缝提供；Job 的 `follow`/`kill` 自动契约与 UI 能力门控已覆盖，旧适配器仍保持只读 Jobs 行为；非空真实 Job 的跟读/停止和 VS Code 现场回放尚未验证，故保持 `PARTIAL`。
- 此前有 `tests/live-dsh/run.spec.ts` 与 `surfaces.spec.ts` 的 managed smoke 执行记录，但现存信息不足以确认这些运行对应 `0.1.5-rc.3`、`0.1.7-alpha.2` 或 `0.1.7-rc.1` 中的哪些 tag，故不将其记作这三个版本各自的真实运行证据。上述版本与 rc.2 的精确入口由契约测试覆盖；alpha.2/rc.1/rc.2 的 `turnWindow` 分页和 alpha.2 `projectContent()` 映射也有自动测试。隔离 DSH home 没有历史会话或非空 Job，tag-specific 历史读取、projectContent 实际产出与 Job follow/kill 尚未回放；能力保持 `PARTIAL`。
- DSH `0.1.5-rc.3` 有独立 `rc153` 身份；rc.2 到 rc.3 的 Connection/Gateway、typed Remote、Session Controller 与 `core/tools/src` 运行时源码无差异，包元数据、lockfile 和依赖策略工具有变更，故沿用已核对的 Session v3 wire，但不让其他版本凭相近版本号继承。固定 SHA `47f943...` 的旧 `rpc-map.ts`/`events.ts` 仅作为历史 Host API 基线，不是 rc.2/rc.3 的比较依据。
- Webview 不接触 endpoint、进程句柄、凭据、文件系统或网络；所有 DSH、文件、进程和 Secret 操作由 Extension Host 负责。
- 代码与自动测试已经覆盖若干条目，但完整的 DSH 版本矩阵、VS Code Webview 现场回放、跨平台发布验证和可访问性人工验证仍是主要缺口，因此当前条目保持 `PARTIAL`。

## 产品边界

- 不复制 DSH Web 的 Right Sidebar/Dock/Split/Floating、独立文件树、PTY Terminal、Browser 和 Open In 应用目录；插件使用 VS Code 原生编辑器、资源管理器、终端、分栏及已有 Host 打开入口，这不表示实现了 DSH Terminal Controller 或 `workspaceFiles` API。
- RC2 Plugin Manager 已接入动态插件与 registry 清单、显式 spec 检查、安装/取消/卸载及可选包启停；上游没有通用 registry 搜索接口，因此不提供伪造搜索。RC2 账号登录、资料、余额、bonus 与 Host 打开的 usage/top-up 页面见 AC-01。Cordis 全局管理、Office 转换预览和桌面端专属 onboarding/后台窗口不由本 Webview 冒充实现。RC2 Schedule 创建与管理见 SCH-01；创建通过 DSH 自己的 Agent 工具，运行时功能开关仍以 DSH 设置为准。
- alpha162 已读取上游 `workspace/changes` 的进程内权威 summary/diff，审查按现有工作区所有权限制展示；打开审查时最多回读 100 页历史，进程重启后的快照不可恢复。空快照或全部路径被过滤时通过会话级失效事件刷新 Changes 列表（Host/Webview 回归测试）。权威能力缺失或刷新失败时保留本地列表并显示未更新提示，取消/权限失败不降级。读取失败统一为 AppError，覆盖网络、读取、超时、取消、关闭和畸形 JSON；404 仍表示快照不存在。未复制上游独立审查 tab 或工作区外文件面。
- Plan 提交物从原生/PTC 的 `exit_plan_mode` 结构化参数恢复，在聊天中提供可重新展开和复制的 Markdown 卡片；已加载历史覆盖该能力，未复制 DSH 右栏布局。

## 证据入口

- 自动门禁：`pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- 真实 DSH 只读 smoke：见 [`tests/live-dsh/README.md`](../tests/live-dsh/README.md)；只验证扩展自己创建的进程，不接管外部 DSH。
- VS Code/Electron 验证：见 [`tests/vscode-e2e/README.md`](../tests/vscode-e2e/README.md)；套件是显式 opt-in，不以粘贴运行日志代替验收条件。
- DSH 固定契约、版本边界和降级规则：见 [`dsh-contract.md`](dsh-contract.md) 与 [`protocol.md`](protocol.md)。

## 证据补充

- 已收到的跨会话结构化审批/问题事件可显示等待审批、计划审查或回答，优先于运行指示；解决、重订阅和断线清理。未订阅会话不宣称有完整交互快照；自动测试覆盖，真实 VS Code 交互待验证。
- 当前 alpha162 证据包括：Goal 的权威 get、armed/disarmed 状态、暂停/恢复/清除已通过隔离真实运行验证；事件失效读取、CAS 引用和 UI 恢复按钮有自动回归；变更 summary/diff、历史恢复、Plan 原生/PTC 卡片有自动测试，真实 shell 快照和 VS Code 点击尚未验证。`image/offload` 不删除持久图片引用，模型请求占位文本与客户端图片显示是不同投影；已有附件回读不依赖 `workspaceFiles`，新增 offloaded 图片映射回归通过。
- 附件选择按适配器公开的二进制上传能力判断：旧运行时的二进制编辑器候选禁用，选择/拖放/粘贴在 Host 暂存前拒绝，图片和文本保留。

## 可选 DSH 能力

MCP、LSP、Schedule、Plugin、Workflow、Ralph、第三方 Tool 等能力必须先从 DSH 的结构化目录或能力声明中发现。未声明、未验证或当前版本不支持时，客户端显示不可用或安全降级，不硬编码清单、不把模型文本当作状态、不伪造 RPC 成功。

## 维护规则

完成一个能力后只更新本表的状态和最短证据入口；不要新增按日期排列的审计章节、缺陷流水、门禁编号、终端转录或临时路径。用户可见的变更写入 [版本更新日志](../apps/extension/CHANGELOG.md)，协议变化写入 [`dsh-contract.md`](dsh-contract.md) / [`protocol.md`](protocol.md)，架构决策写入 ADR。
