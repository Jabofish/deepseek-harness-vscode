# 能力矩阵

本表按功能列出当前范围、已有证据和验收缺口。DSH 版本及接口差异见 [上游契约](dsh-contract.md)，分层和安全规则见 [架构](architecture.md)。

## 阅读说明

| 状态      | 含义                                                          |
| --------- | ------------------------------------------------------------- |
| `DONE`    | 实现、适用的自动测试及所需的真实 DSH / VS Code 验证均有证据。 |
| `PARTIAL` | 已有实现，但仍有功能限制或缺少表中列出的验收证据。            |
| `TODO`    | 尚无可验收实现。                                              |

下列能力均为 `PARTIAL`。状态表示验收完成度，具体可用范围以对应行及目标 DSH 的能力声明为准。

“已有证据”中的**实现**只指代码或流程入口；**自动**指契约、单元、集成或组件测试；**DSH**指隔离真实运行；**VS Code**指编辑器内的自动或人工验证；**渲染**指独立浏览器布局验证。各类验证只证明列出的路径，互不替代。代码实现和测试入口本身不证明现场验收完成。

通用测试入口：[Adapter](../packages/dsh-adapter/test/)、[Application](../packages/application/test/)、[Extension](../apps/extension/src/)、[Webview](../apps/webview/src/)、[真实 DSH](../tests/live-dsh/)和 [VS Code](../tests/vscode-e2e/)。

## 产品边界

- 编辑器、资源管理器、终端和分栏使用 VS Code 原生能力。DSH Web 的 Dock、独立文件树、PTY Terminal、Browser、Office 预览及桌面专属窗口不属于本扩展界面；Host 文件打开入口不代表实现 DSH Terminal Controller 或 `workspaceFiles` API。
- 远程工作区使用工作区侧的 DSH 和文件系统。用户显式连接外部 `custom` DSH 时，不建立服务器文件系统与当前工作区之间的映射。
- 模型、Provider、Preset、命令、工具、Skill、插件及可选服务来自结构化目录或能力声明。插件清单与完整插件管理器具有不同范围；上游未提供通用 registry 搜索接口时，不提供该搜索能力。
- 审批、问题、Goal、Job、Workflow 和工具状态来自结构化接口及事件，不从模型文本推断。

协议与版本来源见[上游契约](dsh-contract.md)，安全边界见[架构](architecture.md)，验收规则见[质量流程](quality.md)。
